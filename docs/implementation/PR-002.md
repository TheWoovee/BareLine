# PR-002 — Document engine

State: IN_PROGRESS — UTF-8 Resident core slice.

Read first: [own PR brief](../blueprint/PRs/PR-002_PAGED_DOCUMENT_ENGINE_AND_CORE_UNDO.md). Active contracts: FC-02 source availability/newline summaries and FC-03 owned undo; FC-06 when the bounded scheduler is wired. No broader blueprint scan is required.

This slice supplies a persistent balanced piece tree, typed text positions, immutable owned UTF-8 chunks, CR/LF/CRLF summaries, atomic revision-checked edit transactions, snapshots and owned undo/redo. It does not claim paged-source, legacy-codec, disk-spill or durable-recovery completion.

The PR-001 neutral interfaces needed by this slice are available. PR-001's remaining UI/acceptance work stays open in its own note.

Validation will use one deterministic edit oracle that covers mixed newlines, UTF-8, snapshots and undo/redo, plus focused atomicity/budget checks. No giant committed fixtures.

Delivered: persistent AVL piece tree with bounded 64 KiB leaves, streaming range iterator, CR/LF/CRLF cross-piece summaries, logarithmic line-start lookup, revision validation, immutable snapshots, shared byte/undo budgets and content-state undo/redo. Logical document actors share two workers; bounded queues return non-droppable edits on saturation and notify the UI on completion.

Availability layer: ByteSource trait with Resident/Paged memory caches, immutable returned pages, source-generation rejection, explicit Pending/Unavailable, bounded LRU, retained-page accounting and verified sealing. The producer must run on an I/O worker and perform before/after identity checks. This does not yet constitute complete file-backed paging.

Six focused tests passed, including 100,000 deterministic random edits with mixed EOL/Unicode and undo-all/redo-all, snapshot stability, AVL balance, line navigation, atomic failed batches, shared budgets, 5,000 logical documents on the bounded pool, eviction and changed-source sealing.

Remaining: actual viewport-first file reader, private disk-backed spill/transcode store, quota handling, source-to-piece integration for Pending/Unavailable roots, cancellable sparse indexing, selection metadata in core undo, typing grouping and scheduler shutdown/fairness hardening. Paged/disk acceptance is not marked complete.

## PR-002 closure audit — 2026-09-07 (source inspection only)

This append supersedes the earlier remaining list; it is not new test/acceptance evidence. PR-004 owner confirmed this note is free and document source is frozen for its integration gate. No source files, tests, build or desktop checks were changed/run for this audit.

Already present beyond the first slice: `file-io/src/source.rs` has identity-checked page reads and incremental Resident fill; `document/src/paged.rs` has source-backed balanced roots, materialized atomic edits and owned inverse history; `file-io/src/codecs/disk.rs` has private raw/text/provenance stores, cancellable steps and quota recomputation before growth. `document/src/group.rs` plus `service.rs` already coordinate Resident linked commit/undo atomically. Do not recreate those implementations.

Concrete remaining implementation, in dependency order:

1. **Owned spill storage and root integration.** `tree::Segment` still owns `Box<str>` and its RAM reservation. Resident history retains complete before/after roots; Paged history retains owned inverse/inserted roots. `Budget::reserve` rejects at the cap; neither path evicts owned chunks to disk. Introduce immutable owned-store references and an explicit nonblocking read result for spilled segments, with a bounded cache and live-reference lifetime. Stage disk writes outside actor locks, then validate document/content identity and atomically attach prepared roots. Reuse platform-neutral storage contracts; implement file I/O in file-io, not Windows APIs in document. Existing synchronous `DocumentSnapshot::chunks` cannot silently perform disk I/O: preserve it for guaranteed Resident bytes and explicitly migrate spill-capable consumers to window requests. This is the largest closure dependency, not a local Budget tweak. Large transactions need the same prepared transaction-store path instead of full inserted/inverse Strings in actor requests. Only release RAM after referenced owned bytes are safely available; snapshots/undo/recovery must retain backing stores.
2. **Sparse navigation and caller integration.** `SparseLineIndex` is only referenced by its own module/tests. It supports sequential observe, checkpoint-before-byte, cancellation and full reset, but lacks byte-to-line refinement and line-to-range requests/prefetch. Add bounded `LineLookupRequest` state with Ready/Pending/Unavailable, captured document/content identity, progress and cancellation; scan from retained checkpoint using existing WindowRequest. Reuse CRLF boundary state; invalidate checkpoints from the earliest edited offset while retaining safe prefix. Wire index ownership and work scheduling into the Paged actor/viewport after PR-004 releases those files. Resident completion should publish index completion rather than requiring a second unbounded scan.
3. **Core history metadata and typing grouping.** `EditTransaction` has only revision/edits; both history representations omit selections and edit origin. Editor-surface carries separate selection stacks. Add an opt-in transaction envelope (existing apply API defaults to an explicit boundary), neutral ordered anchor/caret sets, edit origin, monotonic typing time and explicit boundary token. Store before/after selections and source in core history and return them with undo/redo completions. Merge only adjacent ordinary typing within the configured interval with matching selections/content lineage; paste, multi-cursor, macro, extension, replace-all and cursor movement terminate groups. Keep original semantic edit order when normalization sorts ranges. Do not merge linked UndoGroups. Migrate editor selection stacks only after compatible core APIs exist.
4. **Retention policy.** Both cores use unbounded history-entry vectors constrained only by payload charges; there is no configurable change-count policy or semantically safe clean-checkpoint retirement. Add a bounded history policy and expose retained entry/payload/disk counters. Retire only unreferenced complete history units; keep linked groups atomic or refuse their coordinated undo when any member no longer retains the group. Preserve saved ContentState identity when older undo is retired. A disk-spill failure must leave the last committed edit/history intact.
5. **Actor completeness/fairness/lifetime.** `service.rs` drains one actor until its queue empties, so a replenished hot actor can monopolize a worker; Scheduler Drop detaches unfinished workers and services keep senders alive. Add a finite actor quantum and a bounded ready/deferred scheduling mechanism that cannot lose or deadlock a non-droppable edit when the ready queue is full. Add explicit close semantics so submissions become Closed and queued work is resolved, with joining off the UI thread. Supply snapshot/subscription/prefetch APIs (current API publishes only per-request completions); bounded subscribers coalesce stale revision notifications. Preserve group stable-ID guard ordering and existing nonblocking submission.
6. **Effective resource settings.** Settings exposes Resident threshold and transcode quota, while Workspace constructs fixed 256 MiB byte and 128 MiB history budgets. Add the missing document page-size/page-cache/aggregate-cache and undo aggregate-RAM/change-budget controls, validated effective values and per-process shared accounting. Wire new work to the effective limits; do not turn each tab into a separate aggregate budget. Transcode free-space quota logic already exists and should be reused, with recovery accounting separate.

Ownership/graft plan: until root explicitly transfers files, PR-004 retains document dependency edits, all file-io codecs/source/recovery/lifecycle, editor-surface and app integration. The first independently assignable source slice after the gate is `document/src/service.rs` (actor scheduling/publication) with additive API only, or a new `document/src/history.rs` containing the neutral metadata/policy types; actual lib/paged/tree wiring must be assigned as one coordinated core slice. Spill requires joint tree/source/window and file-io ownership and must not be started as an isolated storage helper with no reader integration. Sparse index may be extracted into a dedicated module only with an agreed narrow paged.rs module/re-export graft. Settings/app wiring follows those core contracts, not concurrently with active workspace edits.

Closure evidence still required after implementation: reuse the existing 100k edit oracle and owned-inverse/source-change tests, adding only focused cases for spill across multiple tabs with retained snapshots/undo, failed/cancelled spill atomicity, sparse lookup CRLF/stale/cancel behavior, typing boundary/selection restoration and hot-actor fairness/close. The sole integration owner runs the agreed compile/test gate; large 100 MB/1 GB/5 GB streamed fixture and native acceptance results remain explicit evidence tasks, not implied by this source audit. PR-002 remains IN_PROGRESS.
