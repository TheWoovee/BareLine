Status: source complete; coordinated component and transport gates passed. Native manual acceptance and external release prerequisites remain pending. No production catalog key, runtime certificate pin, signed publication or online activation is supplied by this development build. `compiled_trust()` fails closed and the editor has no unsigned/test-key UI bypass.

## Delivered source

- The MIT OR Apache-2.0 protocol/SDK define authenticated framed requests, capability generations, bounded staged edits, immutable text/raw domains and a stable component WIT. Wasmtime/WASI and the approved host-only Tokio dependency remain confined to the optional host; no runtime is loaded into the editor. Interactive execution retains 5 seconds/50 million fuel and 128 MiB memory. A signed `background_commands` declaration permits an explicit user-selected 120-second/200-billion-fuel invocation; it does not let a guest select its quota.
- The native launcher verifies and holds the runtime executable and component, authenticates nonce/PID, and owns a kill-on-close Job Object watchdog covering compilation, blocked WASI, cancellation and execution. Source lifecycle receipts distinguish requested, actual process start, authenticated pipe, drained process and prelaunch rejection by invocation generation and PID. No polling of UI strings establishes process readiness.
- The manager consumes signed offline extension catalogs and the release-owned verified native runtime provider. Installed records, approval state and runtime digest are saved atomically in `manager-v1.json`. Reload verifies retained signed receipts and every extracted byte. Fresh metadata gates new installs/updates; unchanged accepted packages remain usable offline after catalog expiry while current owner identity/publisher policy is checked. The editable index is never signature or manifest authority.
- Updates intersect prior approvals with the new signed capability set; added capabilities disable the updated extension until review and approval. Disable cancels the running invocation and revokes its contribution generation immediately. If another manager write is pending, the disabled state is applied to its completed index and persisted next. Disabling retains remembered approvals and installed bytes. Explicit removal deletes only enumerated package files plus its two fixed cache records; update cleanup runs after the new index commits and reports cleanup failures without reverting the successful installation. Runtime removal uses the release provider's verified owned-file list.
- Owned command identities retain extension ID, manifest command ID and generation. Palette dispatch revalidates that exact identity independently of manager selection. Both installation and runtime projection enforce the aggregate 1024-command limit against verified manifests, not editable count hints. Disabled rows have no live guest process or guest heap.
- The native manager exposes Installed/Discover/Updates/Disabled package cards, actual offline install/update/remove controls, permission review/approval, command selection, explicit background execution and Cancel. Structured argument lines reuse bounded single-line TextFields with selection, clipboard, undo and IME; only committed lines are serialized, capped at 4096 bytes. Results are paged and copyable. Visible controls, argument values, results and status have accessibility nodes/actions using the same hit targets. Existing native parent hooks route draw, IME caret, command dispatch, accessibility and completion pumping.
- The production invocation caller supplies actual captured readers. Normal UTF-8 originals are opened with a sealed handle and checked against the captured disk fingerprint on a worker. Transcoded resident originals use retained raw bytes; paged originals use a retained sealed store. Paged TextView requests use immutable paged snapshots and bounded windows/page resolution. Raw reads never substitute edited/decoded text. Paged invocation is read-only. Resident formatter proposals remain staged until successful child termination, and are refused when retained opaque-byte provenance would be lost; actor identity/revision/read-only checks still own final application.
