# U13 review R2 — do not block UI on the line scanner

Follow-up call-path review after the focused EOF correctness test passed found a responsiveness defect: GlobalNavigation::start holds index.lock() throughout resolve/lookup, including page resolution and cancellation waits. U13 added indexed_line_count using the same blocking lock and calls it from PagedEditorSurface::pump on every refresh_gutter_accuracy; status index_progress also blocks. A large line scan can therefore stall UI pumping and delay the very cancel event intended to stop it. The earlier EOF test waited for worker completion before querying and did not cover this case.

Required correction: expose nonblocking, generation-qualified progress/exact line-count receipts for UI reads without acquiring the long-lived worker index lock. Preserve terminal Known knowledge for the same generation; do not turn a temporarily contended exact index back into an estimate. Ensure cancellation/stale generation transitions remain truthful. Add a controlled held-scan barrier test proving UI pump/status reads and cancellation submission return before scan release, then confirm final exact state after completion. Keep the existing near-EOF/EOF test.
