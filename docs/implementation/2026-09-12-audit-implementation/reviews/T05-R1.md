# T05 root review — discard safety and retained worker ownership

Reviewed `431e700c9f013b3834040eeb9d89bcfc5da13fbc`. Changes requested; not integrated. No Cargo run for T05.

Moving materialization and retirement work off the UI thread is appropriate. The proposed implementation still needs the following corrections before qualification:

1. `purge_directory` holds a Windows directory guard that denies deletion while calling pathname `remove_dir`. It also falls back to unguarded deletion for Unsupported providers and has unbounded enumeration. Reuse T01's verified directory identity, delete-handle and retained-proof protocol, with bounded work and no unguarded production fallback. A directory guard does not prevent late child creation; preserve retirement authority on uncertain failure.
2. The retirement executor catches panics outside the operation, but the operation has no terminal guard. A panic in preparation/draining or cleanup can leave `running` and phase pending without notification, while moving ownership out of retained state. Preserve known ownership outside fallible draining, publish a retryable terminal failure and wake the caller on unwind.
3. Completed entries in `retained_discards` survive until a user invokes Retry. Prune completion automatically, deduplicate warnings and scheduling, and bound retained bookkeeping without dropping unresolved ownership.
4. `run` retains a prior failure even when a later retry removes the path. Only unresolved failures may publish CleanupPending. Tests must distinguish durable tombstone publication from physical cleanup completion.
5. `ApplicationDiscarding` filters its captured exact revisions against current documents and can then force exit when the stale set is empty. Edits or newly opened dirty documents during pending discard must not bypass consent. Revalidate the complete current document set before exit. For document close, resolve stable ownership across index shifts and preserve consent revision; either freeze only the discard target temporarily or safely re-arm recovery when new edits cancel closing. Unrelated documents must remain editable.
6. Resident discard state persists after reopening a retained closed buffer, disabling future checkpoints. Re-establish fresh recovery ownership on reopen. Restore the removed close/restore-last-closed coverage with asynchronous completion handling and verify subsequent edits are recoverable.
7. Recovery inspection/materialization errors and cancellation are converted to None by `.ok().flatten()`. Only a legitimate over-limit result may choose paged fallback; actual failures must remain terminal and truthful.
8. Add gated actual shell close/exit tests for new edits, new documents and index shifts; actual Windows cleanup obstruction/identity/junction coverage; unwind and eventual-success retry coverage. Rebase later against T02/T18 and coordinate T04 without overwriting accepted interfaces.
