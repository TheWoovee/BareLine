# Implementation plan — fixes for the 2026-09-08 full review

Source of findings: [`docs/qa/REVIEW-20260908-CODE-AND-UX.md`](../qa/REVIEW-20260908-CODE-AND-UX.md) (UX-nn, ARCH-nn) and [`docs/qa/evidence/review-20260908/review_security.md`](../qa/evidence/review-20260908/review_security.md) (CRASH-nn, LEAK-nn, SEC-nn). Baseline `51cd4c0`.

Ordering principle: anything that destroys user data or kills the process goes first, then the things every user sees in the first five minutes (menus, prompts, large files), then panels/dialogs, then polish, then code health that reduces the cost of everything after it. Estimates are engineer-days for someone already familiar with the tree; add review and native verification on top.

Every item lists the files to touch, the change, and an acceptance check. "Native check" means a scripted run of the built binary (the review used SendInput + screenshots; `xtask` should grow a `journey` runner so these become repeatable, see P5-9).

Recommended immediate change to the tracker: downgrade PR-005, PR-009, PR-010, PR-011, PR-016, PR-018, PR-020 and PR-027 from `IMPLEMENTATION_COMPLETE_PENDING_ACCEPTANCE` to `IN_PROGRESS` in `docs/IMPLEMENTATION_STATUS.md`, citing the finding IDs below. The current wording is not defensible against the running binary.
