# PR-006 implementation and evidence

Power editing is implemented in `crates/editor-surface/src/power.rs` as revision-bound transaction preparation. The integration layer must submit each returned transaction to DocumentService; incomplete source snapshots are rejected. The preparation APIs never write files.

Delivered core behavior: normalized multiselections, grapheme-safe insertion/deletion, caret toggling/above/below, occurrence selection, primary rotation/collapse, line expansion, rectangle insertion/paste/copy, numeric column sequences in bases 2/8/10/16, same-document drag move/copy, line transforms, case and whitespace transforms. Rectangle tab spans preserve unselected columns; wide graphemes remain whole. A renderer-metric constructor is provided for display-column maps; fallback width is deterministic but is not a substitute for measured shaping in every script.

Selections are sorted by text byte offset. Overlapping ranges and coincident carets merge before edits; adjacent non-overlapping ranges remain independent. Mutation produces one transaction for one revision. Preparation and clipboard budgets reject oversized work, including excessive configured tab widths. Large selected transforms currently reject beyond their explicit in-memory budget rather than spilling or streaming; occurrence selection similarly bounds its document read. Cross-document drag needs the FC-06 linked-root coordinator and is not advertised as complete by this module.

Clipboard history defaults off, allocates no entries while off, stores at most 20 entries / 16 MiB total / 4 MiB each, evicts oldest entries, and releases its contents when disabled. No persistent interface exists. CommentProvider/NoComments expose metadata only and return the specified unavailable reason before language integration. Ephemeral bookmarks map their text anchors through edits; view integration must call mapping after successful commit.

Evidence: Windows headless `cargo test -p bareline-editor-surface power::tests --lib`: 4 passed in 24.43 s. This covers 10,000 cursor insert/delete/undo, exactly one history entry per transaction, Unicode rectangle insertion across tabs and short rows in all four bases, incomplete-source rejection, overlap merging, budget rejection, mixed-EOL duplicate removal and blank-row-preserving line movement. Additional metadata/partial-tab regression tests are recorded after execution below.

Remaining integration/acceptance: full command routing and multi-selection history/painting, Column Editor/history popovers, hidden-line view rendering/reveal, measured display metrics, cross-document atomic moves, renderer and physical rectangle input at reference dimensions. Desktop visual and physical input validation is pending because the desktop is locked; it must not be treated as source implementation evidence.

Additional evidence: `cargo test -p bareline-editor-surface power::metadata_tests --lib`: 2 passed, including disabled/evicted clipboard history, >4 MiB rejection, 16 MiB cap, right partial-tab preservation and enormous tab-width rejection. Registry declares stable contributed command IDs and a transform lookup for composition-root dispatch. Occurrence selection has a bounded separate selection-history helper. CrossDocumentDrag only prepares both revision/snapshot-bound transactions; atomicity remains the document coordinator's responsibility. Clippy was attempted but workspace manifest discovery temporarily failed while another agent created extension-sdk; this is not a passing check.

Final focused checkpoint: `cargo clippy -p bareline-editor-surface --lib -- -D warnings` passed. `cargo test -p bareline-editor-surface selected_block_duplicate_and_rectangle_round_trip --lib` passed (1), proving selected multiline blocks duplicate in block order and rectangle copy/paste preserves tab/CJK/emoji boundaries and short-row padding. Total unique power tests exercised: 7. The newly registered `editor.selection.duplicate` duplicates the selected text while `editor.lines.duplicate` expands and duplicates the logical line block.

## Source closure checkpoint (2026-09-08)

The native `windows_app/power.rs` consumer now opens Column Editor (text or numeric arguments), an ephemeral clipboard-history picker, routes plain-text paste and bookmarked-line copy/cut/delete, handles keyboard/mouse rectangles and Ctrl+Click carets, and retains cross-document drag coordinator tickets until completion. `power/consumer.rs` supplies the view-side API. Rectangle typing/deletion uses projected transactions; ordinary copying now reads all selections or the rectangle with the clipboard budget. Rectangle indent only inserts at the column; unindent removes whitespace immediately before it.

Power command acknowledgments publish only after successful worker completion; pure view commands publish after successful execution. A single bounded ordered receipt stream shares a process sequence with verified search receipts, preserving macro order across input and contributed commands. Replay uses explicit argument maps and never reads the clipboard or opens a form. Dialog targets are checked against document identity and revision before submission. Clipboard admission failures preserve the operating-system copy result and report the history error.

Manual hidden ranges are independent from language folds, merged for display, and reveal when the caret enters them. View-only compare spacer rows participate in logical/visual mapping and are skipped for text and line-number rendering. Font-family changes invalidate only editor layout IDs; body and IME text use the configured family. The source-only regression additions cover hidden ranges, receipt bounds, rejected replay and logical scroll mapping.

No independent build, test, formatting or physical-input run was performed during this source pass; integration owns the combined gate. Earlier seven passing power tests remain historical evidence, not proof of the added consumers. Outstanding source limitations: huge selected transforms still reject the bounded String transaction budget instead of external sorting/staging; fallback display widths remain used in rectangle projection; private rectangle clipboard metadata is not supplied. Native visual/physical acceptance remains unverified. These limitations prevent treating all PR-006 acceptance as complete.
