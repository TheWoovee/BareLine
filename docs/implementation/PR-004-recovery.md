# PR-004 durable recovery

Implementation in progress: bounded immutable segment ownership, CRC32C journal ordering, sealed baseline verification, checkpoint publication, validated-prefix replay and durable retirement. This backend is separate from session layout persistence. Its initial integration uses complete UTF-8 snapshots; incomplete recovery exports edits with an explicit gap report.

Delivered `crates/file-io/src/recovery/mod.rs`: fresh-directory single-writer ownership; immutable inverse/inserted segments (16 MiB transaction cap); SHA-256 length/hash references; versioned binary length/CRC32C-framed transaction records (1 MiB record / 64 MiB journal bounds); receipt publication only after segment and journal sync; validated previous-checkpoint preservation; cancellable 64 KiB baseline copying with mandatory post-copy generation verification; and fixed-buffer disk-backed replay into a create-new recovered copy. Checkpoint manifests include source generation and codec catalog version. Manifest/journal truncation below the checkpoint receipt watermark is visibly CorruptTail. Baseline-backed inspection verifies inverse applicability and reports only the validated prefix, preventing an unapplicable transaction from being labelled Complete.

Recovery inspection distinguishes Complete, EditsOnly, CorruptTail, SourceUnavailable and Discarded; it exposes both validated-prefix receipt and checkpoint receipt watermark. Edits export includes owned segments, offsets and a versioned gap report. Discard atomically publishes a durable tombstone; collection requires a certified complete live undo/checkpoint reference trace and preserves referenced blobs. It never recursively deletes a recovery directory. Failure preserves the last receipt and the event-driven RecoverySchedule suspends automatic retries until Retry; it computes the five-second/256 KiB threshold while retaining edits newer than a save/flush receipt.

Evidence: `cargo test -p bareline-file-io recovery:: --lib` — 12 passed on Windows. Boundary injection covers segment written/flushed, journal written/flushed and checkpoint written/committed; tests cover corrupt tail, clean-boundary and zero-length journal rollback, missing/corrupt segment/baseline, invalid inverse, generation-change sealing, cancellation, create-new no-overwrite recovery, gap export, duplicate writer, durable discard, live-reference-safe GC and scheduling. `cargo clippy -p bareline-file-io --lib -- -D warnings` passed. Tests use in-process I/O failure injection; physical process-kill/power-loss tests are not claimed.

Application scheduling and actual receipt delivery are separate integration responsibilities. Backend deliberately uses disk scratch replay for inverse validation, so Complete inspection has additional background I/O. No five-second durability promise applies while storage is unavailable. Baseline generation verification must be supplied by the source owner; verified-original-only fallback is not implemented, and missing sealed data remains honestly incomplete. This source change does not itself establish lock-screen UI/physical-input evidence.


## Native/runtime source closure batch — 2026-09-06

Primary restore rebuilds source spans (including undo-restored opaque bytes), refuses stale recipes/tombstones, and opens dirty with Save As required. Root recipe decoding has a 128 MiB byte cap, 65,536-piece cap, transient budget charge and retained tree-node charge.

Resident and untitled documents now observe successful immutable editor snapshots through a coalescing background checkpoint worker. Their root recipes preserve original Resident chunk provenance; untitled chunks remain owned text. Complete current-state baselines and atomic receipts support the same primary restore route. A clean Undo is checkpointed before stale generations are retired; Save retires the matching generation. Paged Save also retains failed retirement paths for Retry.
