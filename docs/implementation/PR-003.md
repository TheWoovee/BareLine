# PR-003 — Editor surface

State: IN_PROGRESS, Resident editor slice. Read the [own brief](../blueprint/PRs/PR-003_VIRTUALIZED_EDITOR_SURFACE_INPUT_AND_SELECTION_MODEL.md), then its visible-line/input/selection contract. The consumed foundation is the PR-001 text backend, PR-002 Resident snapshots/transactions/scheduler, and PR-023 tab/scrollbar geometry.

Implement real editing through DocumentService, bounded visible-line layout and shaped caret/selection. Remaining paged-source, advanced selection, wrap, hidden-line, accessibility and physical IME acceptance stays explicit; this slice does not complete those dependencies.

PC remains locked. Use RecordingBackend and native compilation; do not attempt desktop automation or claim mock equality.

Delivered Resident slice: asynchronous queued input, snapshot-driven visible-line layout cache, grapheme navigation/editing, stream selection, undo/redo selection restoration, scrolling/caret reveal, composition overlay, native clipboard command hooks, status derived from actual content, dirty tabs and tab switching. Shaping is capped at 64 KiB per visible line fragment; oversized lines show continuation instead of allocating a full-line layout.

The RecordingBackend integration test passed queued multiline Unicode typing, composition cancellation without a content-state change, undo/redo, caret geometry and frame output. Windows integration compiled.

Remaining: full multi/rectangle selection, mouse drag, preferred-column/visual BiDi navigation, horizontal scrolling/wrap, unknown-page placeholders, very-long-grapheme navigation, hidden lines and actual physical IME/clipboard interaction. The initial long-line fragment view is bounded but is not the completed 20 MiB-line navigation feature.
