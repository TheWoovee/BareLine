# PR-020 supply-chain source controls

Source implemented 2026-09-08; CI execution and whole-PR acceptance pending.

`supply-chain.yml` applies the existing `deny.toml` policy, RustSec audit and CycloneDX generation. Cargo tools use exact versions with locked installation; application metadata/builds require the checked-in lockfile and toolchain. CycloneDX lacks a locked option, so its lockfile is checked for changes afterward. The release owner's `generate-sbom.ps1` merges and normalizes the editor and update-helper Cargo SBOMs and adds native inventory/source hashes into payload `SBOM.json`; `generate-notices.ps1` supplies the exact dependency and bundled Lexilla/Scintilla notices. The optional host has its separate Cargo SBOM and executable hash; it is not silently included in the editor package.

Two independent fresh Windows 2022 jobs build the same commit without restored caches. The comparison gate requires identical commit, compiler metadata and SHA-256 hashes for editor, update helper and optional extension host executables, plus normalized payload comparison and deterministic ZIP hashes through release-owned scripts. `/Brepro` requests deterministic PE output; it is not evidence that all compiler/native inputs are deterministic. Hash differences fail the gate and require investigation. Installer/signature/timestamp reproducibility remains distinct from this unsigned payload gate.

Workflow permissions are read-only, checkout credentials are not retained, and action revisions are pinned. Signing is disabled unless `BARELINE_SIGNING_ENABLED=true`; it then requires a tag, successful dependency/reproducibility gates, default-branch ancestry, the `release-signing` environment, and explicit `BARELINE_PROTECTED_RELEASE_ENVIRONMENT=true`. The repository owner must actually configure branch protection and environment approval before setting that attestation; a YAML environment name alone cannot establish protection. The signing script requires configured tool/certificate/timestamp/publisher variables and records pre/post hash evidence. No production credentials are supplied, no signing executed and no release publication configured. Hosted certificate provisioning/SignPath enrollment and final signed packaging/minisign verification remain external release prerequisites.

No local tools were installed and no build/audit/check was executed for this source batch. Proposed coordinator verification: parse workflow, run dependency policy/audit/SBOM once in CI, and run the two clean build jobs with comparison. Do not close reproducibility or advisory acceptance from source review alone. Current dependency-policy failures must be resolved by their owners, not waived automatically.

Tool syntax/version references: [cargo-deny](https://embarkstudios.github.io/cargo-deny/), [RustSec](https://github.com/rustsec/rustsec/tree/main/cargo-audit), [CycloneDX](https://github.com/CycloneDX/cyclonedx-rust-cargo/tree/main/cargo-cyclonedx).

The release-owned merger retains both packaged executable graphs with canonical references and native/source inventory. This closes the earlier workflow/script source dependency.
