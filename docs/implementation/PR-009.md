## Delivered behavior

- Explorer uses the PR-023 virtual tree. Opening a root does no directory enumeration. One cancellable listing runs at a time; each page visits at most 4096 entries, including excluded entries. The tree retains at most 32768 nodes. Load More advances its retained directory cursor; at the resident ceiling it releases an earlier page or another branch. Re-expanding evicted branches restarts discovery. There is no eager recursive traversal, hashing, or file-content read.
- Directory watches feed a coalesced set of changed branches. Refresh retains IDs and loaded descendants for surviving paths, removes disappeared entries, and remaps tree expansion/selection through `Tree::replace_child_ids`. Expanded directories are prioritized for the bounded native watcher service; its overflow status reports omitted coverage. Refresh Workspace remains available. Directory guards live through enumeration, and linked directories are not traversed.
- Search exclusions come from effective user/opted-in workspace settings. Basename and root-relative `*`/`?` patterns are bounded to 256 patterns of 256 characters; `folder/**` excludes that folder before traversal. Star matching can cross path separators. Excludes affect discovery only, not stored path identity.
- Native create-file/create-folder operations are create-new. Rename is handle-based and atomically refuses destination replacement. The coordinator repaired and verified the shared rename ABI buffer length; that verified code remains unchanged in this closure. Rename/delete require closing documents at or beneath the selected path.
- Explorer Delete performs an atomic no-traversal move to a unique `.bareline-deleted-*` sibling, retaining all contents. Undo Delete restores it without replacing a collision. At most 32 outstanding deletions are retained in the session. Entries are never automatically purged at shutdown; their reported retained path remains available for explicit rename after restart. The lower-level permanent delete API remains nonrecursive.
- Document List consumes tab metadata, uses the virtual variable list, and provides name/path/tab-order sort, filter, activate, save and close. Its metadata-generation accessibility IDs reject actions from an obsolete tab-list projection.
- Rust/TOML outline extraction now belongs to `syntax::outline`; lexical declarations expose text offsets, bounded extent and nesting. TOML multiline-string state survives chunks. The panel publishes at most 8192 symbols in 256 KiB chunks, filters metadata outside painting, follows the caret, and cancels old document/revision work. Navigation checks source identity/revision and anchor bytes. Outline accessibility IDs include the projection generation.
- `syntax::outline` imports Notepad++ functionList XML into a version-1 TOML definition. PCRE2-compatible function and chained name expressions are imported; class extents are explicitly approximated from mainExpr. Unsupported elements/attributes and incompatible regex rules produce a deterministic report. Input, aggregate patterns, XML depth and rule counts are bounded; DTDs/entities, malformed nesting, duplicate attributes and invalid TOML are refused. Regex execution uses the existing bounded search engine. Import cancellation reaches parsing and regex validation.
- Native Import Function List, Load Definition, Export Definition and Cancel Import commands are wired. Import binds to the active document's extension and creates an editable mapping-report tab without changing the primary active-document identity. Export stages, flushes and atomically commits TOML while retaining the destination directory. Definition loading retains trusted source ancestry. No executable configuration or catalog mutation is introduced.
- The document map uses 256 fixed density buckets and at most 128 bytes per sample. It navigates by text-byte ratio, aligns to valid boundaries, validates the source before navigation, and draws a viewport indicator without exact line totals. Sampling/unavailable data is labelled; an incomplete source never becomes an exact-total claim.
- Workspace/Documents remain left-docked alternatives; Outline and Map occupy the right. Panels start hidden, preserve runtime toggle/focus state and yield input to the command palette. Root opening calls the settings owner's asynchronous `set_workspace_root`; merely opening a root does not create configuration files or grant workspace preferences.
- Actual visible explorer/document/outline semantic nodes, filter SetValue, Focus/Invoke navigation, and focus reporting are wired through the accessibility owner. Explorer semantics retain hierarchy. Worker disconnection is terminal and reported instead of leaving a permanently busy command.
