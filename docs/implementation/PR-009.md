# PR-009 — workspace navigation

Read PR-009, FC-02/09 and UI-ED; inspected the current workspace-split image at its reference dimensions. No new dependencies.

Delivered source:
- Lazy explorer uses PR-023 virtual tree and stable in-session node IDs. One background directory listing at a time; at most 4096 entries per expanded branch and 32768 resident nodes. Caps/error states are explicit. Only expanded levels are read. Windows consumers retain actual no-follow read capabilities through each enumeration, preventing ancestor retargeting and link cycles.
- Native create-new file/directory, handle-based no-replace rename (including directory rename), and nonrecursive handle-based deletion. Retained parent handles deny deletion during each mutation; reparse/offline/device/unsupported filesystem paths fail. Existing destinations are never overwritten. The UI requires closing an open document before renaming/deleting its file to preserve tab path consistency.
- Metadata-only document list uses PR-023 variable list, sorting by name/path/tab order, typing/Backspace filtering, activation and save/close through existing shell commands.
- Progressive outline publishes bounded 256 KiB chunks, supports Rust lexical declaration anchors and TOML table headings, tracks TOML multiline strings, caps symbols at 8192, supports filter/follow-caret, and validates document identity/revision plus anchor text before navigation. It is a lexical fallback, not an AST. Unsupported languages say so.
- Progressive fixed-size 256-bucket byte-density map samples at most 128 bytes per bucket off-thread. Navigation and viewport rectangles use byte ratios and remain independent of exact line counts. Partial sources are labelled.
- `windows_app/workspace_panels.rs` supplies concrete draw/input/dispatch/pump consumers, with default-hidden panels and command palette actions. Parent integration owns final hook insertion.
