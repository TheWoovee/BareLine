# PR-004 session persistence

Implementation in progress. Owns bounded versioned JSON manifests, lossless platform paths, restore ordering, and atomic local manifest publication with previous-generation recovery. No document path is accessed during decoding. Session import requires the normal path trust evaluation when the app later opens each document.

Delivered bounded versioned JSON encode/decode (8 MiB, 10,000 entries, bounded strings), schema-zero migration, lossless SerializedPath validation, active-first deduplicated restore ordering, and same-directory flushed publication through LocalFileSystem. A validated previous generation is published before replacement; corrupt or unavailable primary can recover that generation with an explicit warning flag. Storage API requires app-owned local paths and serialized I/O-worker use. Import parses data only and confers no document path trust.

Evidence: `cargo test -p bareline-file-io session:: --lib` — 5 passed on Windows. Covers 500-tab scheduling, layout/migration/paths, malformed limits and references, injected permission-denied commit preserving original bytes, previous-generation recovery, and missing storage. No locked-desktop checks apply to this backend. Actual startup/two-worker scheduling and session commands belong to integration; this is not FC-03 edit recovery.

Follow-on app controllers: `crates/app/src/session_ui.rs` captures stable document/tab identity, pin state, exact logical-pixel scroll bits, carets/anchors and pane membership. RestoreQueue requires first-frame notification and explicit caller trust approval, keeps active/MRU order, and caps opens at two in flight. Three focused controller tests passed. `session_service.rs` supplies a lazily created queue-of-four storage worker with cancellable tickets for load/save and named import/export; parsing and atomic writes stay off the UI thread. Shell integration is owned separately.

Schema now has defaulted SessionLayout (single/dual pane, orientation, exact ratio bits, active pane/tabs and sync flags). Invalid imported layout falls back to a single pane while preserving document entries and resetting pane membership. Platform-path decode validates canonical base64/UTF-16 structure so malformed primary manifests correctly fall back to the prior generation. Encode writes through a bounded sink to avoid allocating beyond the 8 MiB cap even for constructed manifests.

Native consumer added in `apps/bareline/src/windows_app/session.rs` for integration-owned parent hooks: first-frame-gated worker load; active/MRU batches of two retained-handle trust resolutions; guard retention until open completion; caret/anchor boundary clamping and exact scroll restoration; persisted order after active-first loading; and asynchronous exit deferral until atomic session write succeeds. It preserves missing/denied paths, cloned-view metadata, folds and pane layout. Actual cloned EditorSurface instantiation remains PR-010 integration work. Closing during partial startup preserves the previous manifest instead of overwriting it with partial state. The worker creates the app-owned state directory off the UI thread. UI input/render validation remains locked-desktop work and is not claimed here.

Additional service contract: ResolvePaths accepts at most two SessionDocument candidates and a PathTrustProvider, resolves only through open_read(PathOrigin::Session), and returns retained TrustedRead capabilities. Imported named sessions must not be routed through the application's automatic local-session policy without a separate trust decision.

2026-09-06 native resume: SessionRuntime is grafted into the real shell. Async close captures authoritative resident/paged document identity and content state, then refuses exit if edits, busy work, I/O, or tab membership changed during session persistence. Native regression passed for intervening edits/new tabs. Paged tabs remain in manifests with global caret/anchor offsets; restore calls bounded asynchronous restore_selection, and stable PagedSnapshot identity survives viewport regeneration. Split view capture/restore now projects actual secondary caret/selection, scroll, orientation, ratio and active pane. Full cross-window paged selection beyond the 65,528-byte viewport is explicitly rejected by the paged adapter. Session persistence is not a dirty-content recovery journal. GUI restart evidence remains a separate QA gate.

Latest native verification: cargo test -p bareline --bin bareline windows_app:: passed 4/4 (three owned tests plus extension cancellation). Split shared edit test now also validates capture/restore of independent secondary anchor, scroll and ratio through a valid manifest. Fold capture/restore uses half-open logical line ranges; secondary peers copy only validated fold metadata from their primary document, preserving independent collapsed state. Paged restore uses filecore restore_selection rather than caret-only viewport navigation. Parent native GUI QA remains required.
