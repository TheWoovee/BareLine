## Required consumer closure — source batch after 376097d

The earlier statement that all UI consumers were integrated was not supported by the bounded caller audit: Interpret, Convert, EOL, binary choices and Resident status still lacked production callers. This batch closes those interfaces explicitly rather than treating codec tests as user-flow evidence.

- `app::encoding` projects the complete FC-01 catalog into stable Interpret/Convert command IDs, BOM choices, whole-document/selection EOL choices and read-only/edit binary decisions. Native Encoding submenus and status-bar hit targets use the existing native menu API. The current main-editor mockup was inspected; no custom layout or colors were introduced.
- `windows_app::encoding` calls the workspace-owned facade for every state change. Dirty reinterpret uses the dedicated default-No confirmation mentioning discarded edits, retained original bytes and unchanged disk contents. Encoding detail displays detection confidence and separate invalid-span/original-byte counts. Binary popup cancellation retains the workspace's read-only protection; editing requires an explicit choice.
- Command context prevents conversion/EOL on a read-only or busy document and prevents enabling a BOM for legacy codecs. A focused dispatch regression is added in source; it has not been run.
- Filecore owns the actual verified-source reinterpret, atomic metadata Undo/Redo, EOL transactions, conversion failure ranges and codec/status persistence. Root owns parent module/register/context/event/pump integration. Until those dependency owners report source readiness and the coordinator runs the gate, this batch remains in progress; no whole-PR implementation or acceptance promotion follows from these new callers alone.

No builds, tests, checks or manual QA were run by this lane for this source batch. Existing disk/OwnedSource codec and native-build gate evidence remains scoped to the checkpoint that produced it.
