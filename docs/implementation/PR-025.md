# PR-025 — bounded diff core closure

Implemented: DONE. Headless acceptance cases: PASS on Windows x64 MSVC, 2026-09-06. Owner acceptance remains pending. Uncommitted workspace; no commit or publication requested.

## Delivered contracts

- OS-neutral synchronous engine, no owned threads or OS imports. Resident immutable snapshots use bounded normalized lines, collision-safe patience anchors, bounded Myers, grapheme/token intraline spans and move-like exact matching. Every retained workspace/output allocation shares a conservative cap. Capped regions explicitly return Coarse; cancellation and source unavailability remain separate.
- Shared full default Unicode 17 folding is used by diff and literal search. Unicode scalar expansions retain original grapheme coordinates. PreserveIgnoredDestination maps case expansions and tab runs back to indivisible original units; overlapping expanded segments merge before transaction creation. CopySelectedRange is the explicit whole-range policy.
- Hunk identities combine unchanged surrounding anchors and changed contents, with occurrence disambiguation. Distinct repeated contexts remain stable after another repeated-context change is inserted earlier. Truly identical duplicate contexts remain inherently ordinal; no unique navigation correspondence is claimed for indistinguishable duplicates.
- PagedCompareJob yields bounded Pending/Progress/Batch/CoarseBlock/Finished states. At most one owned materialized batch is outstanding. Above the global byte cap it validates every source window and retains a single coarse changed extent, trimming verified byte-equal prefix/suffix windows. Identical huge bytes finish Exact without false Changed blocks. Divergent inputs produce one Changed block. Maximum source window is 64 KiB; polling returns control between windows and checks cancellation between sides.
- CoarseBlock is metadata over a potentially huge range. It cannot silently invoke a full-range copy: callers must stage/materialize the reviewed range through their bounded document/file pipeline. PagedBatch.apply validates snapshot identity/revision and materialized windows. Unknown line hints stay None.
- All apply paths produce ordinary EditTransactions with provenance/revision guards; incomplete source prefixes and stale/wrong documents are rejected. Ignored destination bytes are preserved by default; unsupported paged window-edge preservation fails explicitly.
- `cargo run -p xtask --offline -- perf diff` runs full 10 MiB and 1 GiB pairs, checks all input bytes and expected whole coarse ranges, and records timing, source allocation peak, conservative job cap, and OS process lifetime peak commit charge. Evidence is `target/perf/diff.json`.

- Latest 200 MiB-per-side regression completed 419,430,400 bytes in 417 ms under concurrent development load. Earlier isolated sample was 211 ms; these are observations, not merge gates.

- `cargo run -p xtask --offline -- perf diff`: 10 MiB/side 17,576 microseconds; 1 GiB/side 468,341 microseconds. Source allocation peak 131,072 bytes; process lifetime peak commit 2,007,040 bytes for both samples; job cap 4,194,304 bytes. Maximum observed poll 411 microseconds. OS lifetime peak includes harness/prior workload and is distinct from engine allocation accounting. Generated page throughput does not measure disk I/O.
