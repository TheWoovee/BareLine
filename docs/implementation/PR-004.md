# PR-004 — UTF-8 file lifecycle

State: IN_PROGRESS. Read the [own PR brief](../blueprint/PRs/PR-004_FILE_LIFECYCLE_TABS_SESSIONS_AND_CRASH_RECOVERY.md), its staged dependency boundary and FC-04. Conflict previews remain dependent on PR-025; recovery and general paging are not part of this initial slice.

Initial scope: a bounded one-page (1 MiB) valid-UTF-8 open path, BOM preservation, captured-snapshot staged saving, complete destination fingerprint revalidation and fail-closed platform replacement. This is an explicitly limited initial path. Larger files must report that streaming integration is pending rather than loading whole files as an expedient fallback.

No persistent session/recovery promise yet. Production file commands are wired only after their platform adapter and failure behavior are verified. Never truncate an existing destination in place.

Delivered: background UTF-8 open with BOM retention and identity revalidation, complete destination SHA-256 revalidation, staged/flush/replace save and a single bounded I/O worker that serializes saves. Windows adapter restricts this early path to fixed local NTFS, rejects device/ADS/reparse/cloud/hard-link/read-only targets and uses ReplaceFileW or non-overwriting MoveFileExW. Staged bytes are retained on conflict/commit failure. Newer edits stay dirty when a captured snapshot finishes saving.

Open/Save/Save As and native dialogs are wired. Save As currently requires a new target, even if the native dialog approved an existing name; current-file Save uses the captured baseline. Close checks pending operations and unsaved changes. UI remains unverified while the PC is locked.

File → Close / Ctrl+W closes individual tabs with default-cancel dirty confirmation. Pending edits/saves prevent closing their document, and removing another tab remaps save targets without changing document identity. Untitled labels remain stable after neighboring tabs close. A focused headless test passed these dirty/busy and pending-save remapping checks. Runtime operation errors preserve open documents and native file commands instead of exiting; its native notice awaits unlocked-PC verification.

One native temporary-file test passed injected permission failure without original-file change, exact BOM output, captured-state save followed by clean undo and external-writer conflict preservation. It performed no desktop interaction.

Cancellation: queued/running jobs have cancellation tickets; dropping a pending ticket also cancels it. Reads/hash loops check every 64 KiB and saves check each rope chunk and immediately before commit. File → Cancel File Operations requests cancellation without prematurely clearing pending state. Once replacement begins, verification reports the actual outcome despite late cancellation. Blocking OS calls cannot be interrupted by this cooperative mechanism. A focused native test passed cancellation before commit preserving the destination and removing the staged file, plus late cancellation reporting a successful replacement. Stage handles now close before error cleanup on Windows.

Remaining: bounded OS-call timeout policy, retryable Save As replacement policy, read-only open model, full file-state/tab/close model, session persistence, journaling/receipts/recovery UI and diff previews. The arbitrary external-writer race around final replacement remains; no compare-and-swap claim is made.
