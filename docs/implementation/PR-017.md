# PR-017 — Compare Workspace, utilities, export and print

Implementation is IN_PROGRESS. The coordinated Windows gate passed the implemented bounded paths; unrestricted large-hunk merge still depends on the source-splice and streaming recovery contracts. No native printer launch or manual acceptance has been performed in this source phase.

## Delivered source contracts

- Compare uses the normal two-pane editor runtime and PR-025 only. `CompareInput` carries complete resident snapshots or paged piece-tree snapshots with worker-side page resolution. A captured historical pane has its own display identity and a separate original-owner resolver. Open, disk, last-saved, recovery and external-conflict sources feed the same controller. Sessions preserve source document IDs, options and synchronization choices.
- Bounded paged comparisons traverse full sources, including unsaved edits. Cancellation, stale source identity/revision, unavailable data and coarse completion remain distinct. Hunk navigation and the overview operate on canonical byte ranges, including unknown line-index regions. Draw overlays use actual shaped layout ranges and actual pane viewport origins, rather than guessing offsets from visible row numbers.
- Ignore controls map to `CompareOptions`; automatic comparisons debounce on the bounded compare worker. The options dialog exposes Light/Dark/System, semantic swatches, per-state reset, reset-all and a color-blind palette. Gutter glyphs identify state without relying on color. Non-document spacers and synchronized scrolling are supplied by PR-010.
- Resident merges use PR-025 preservation policy. Mixed/paged merges stage bounded reviewed ranges on a worker and submit one revision-checked transaction to the destination actor, with recovery and undo. No merge auto-saves. The existing bounded staging path rejects ranges above 1 MiB explicitly; it is not the planned large-hunk splice path.
- Native utility commands expose MD5/SHA-1 legacy labels, SHA-256/SHA-512, Base64/URL transforms, statistics, HTML/RTF export and print. Visible dialogs show options, known byte size, progress, cancellation, results, Copy, Retry and Close. UI accessibility nodes invoke the same commands.
- Paged utility readers traverse captured text in 64 KiB windows. Statistics and syntax output process logical lines with a 256 KiB line bound. The syntax `StreamLexer` receives sequential, newline-aligned text with exactly one EOF. Escaped HTML/RTF preserve Unicode and effective foreground/background/syntax colors. Oversized or unavailable ranges fail explicitly rather than substituting bytes.
- Export writes a private same-directory stage, flushes/syncs, then uses the platform replacement contract. Errors remove only a stage successfully created by that operation; source files remain unchanged. Print creates an owned printer selection, runs pagination/Unicode shaping on a worker, supports selection/document, font/size/margins, header/footer/line-number/theme options, and aborts unfinished spool jobs on cancellation/error.
