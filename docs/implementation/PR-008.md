# PR-008 — Language catalog and syntax

Status: IN_PROGRESS. This is a native fallback foundation slice, not completion of PR-008.

Authority read: PR-008, ADR-17, FC-01/02/09. Work is local and headless while the desktop is locked. No new external dependencies.

Slice: bounded, revision-owned native Rust/JSON highlighting with cancellable worker requests, compact semantic runs, and verified multiline checkpoints. Requests without valid preceding context remain explicitly provisional and plain. This establishes the fallback API before the Lexilla bridge and complete 15-language catalog.

Pending: Lexilla primary bridge and parity/FFI fixtures; remaining 13 native language definitions; UDL serialization/import/editor; sparse checkpoint cache/invalidation; folding, language settings and command/UI integration; controlled viewport benchmark. Native visual acceptance remains blocked by the locked desktop.

Implemented in `crates/syntax`: filename detection for Rust/JSON; compact semantic keyword/string/comment/number/operator runs; Rust nested block comments, raw strings with hash terminators, Unicode character literals and lifetime distinction; JSON escaped strings and literals. Opaque checkpoints carry actual multiline state and reject foreign documents, languages or revisions. Unknown nonzero context returns Provisional with no fabricated styles/checkpoint. Results revalidate snapshot identity and revision.

Requests cap input at 256 KiB and output at 32,768 coalesced spans. Cancellation is checked throughout lexing. The lazy event-driven worker has one pending slot, cancels superseded running work and wakes the caller on completion. No full-file copy or UI thread lexing is required. Checkpoints are emitted only at newline/EOF boundaries; sparse cache ownership/invalidation remains an integration task.

Evidence (2026-09-06, local Windows, locked desktop): `cargo test -p bareline-syntax --locked` passed 4 focused tests in 0.02s: UTF-8/range correctness and Rust literals/comments; multiline continuation/provisional context/foreign and stale checkpoint rejection; JSON syntax/cancellation/input and output limits; worker supersession and event delivery. `cargo clippy -p bareline-syntax --all-targets --locked -- -D warnings` passed. Rustfmt applied to owned source files. This is lexical highlighting, not grammar validation; Rust macro/interpolation/attribute semantics and full numeric validation are not claimed. No controlled throughput or native visual acceptance claimed.

Integration continuation (2026-09-06): one lazy workspace syntax worker now serves the active viewport. Requests progress from verified checkpoints in at most 256 KiB slices, keep at most 256 checkpoints, and discard result/context on document, revision or language change. Rust/JSON filename detection drives the status language; plain text remains the fallback and unresolved ranges show Styling…. Long lines without an emitted checkpoint remain conservatively unresolved beyond the bounded request rather than guessing context. Cache retention currently follows only the active source, not an aggregate per-document checkpoint cache.

TextBackend now accepts validated UTF-8 foreground ranges on existing layouts. DirectWrite maps those ranges to UTF-16 drawing effects; recording backend preserves the same ranges. Styling does not split shaped runs or alter hit tests; composition uses plain text. Source/foreign-result rejection and unchanged layout IDs/caret geometry passed focused editor tests (2 total). Bounded checkpoint progression and edit invalidation passed app tests (6 total). An offscreen WIC native test created no HWND, proved changed color pixels, unchanged geometry, invalid UTF-8 range refusal and clearing styles restoring identical pixels. `cargo check -p bareline --locked` and app/editor/recording clippy passed. This is headless rendering evidence, not native screen/mock or physical IME acceptance; those remain in the unlock checklist. Full Lexilla/native catalog, folding and UDL remain pending.
