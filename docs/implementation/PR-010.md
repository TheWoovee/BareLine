Source closure candidate, 2026-09-08. The shared integration gate owns compilation, automated execution and acceptance. This note supersedes the earlier resident-only/model-only status. The PR-010 brief, FC-06 and UI-ED contracts were read; the workspace-split and compare-dark mocks informed the independently labelled pane layout.

## Delivered source

`crates/app/src/views.rs` projects the existing PR-004 `SessionTab` and `ViewState` records. It owns no document bytes or second persistent tab model. The native `windows_app/views.rs` consumes that controller with one Workspace editor per document and a separate active secondary view.

- Horizontal/vertical two-pane split with draggable ratio, move/clone/focus/close commands and independent selections, scroll offsets and resident fold state.
- Resident clones share their document service. Paged clones use `PagedEditorSurface::clone_view`, which shares the authoritative actor/recovery state while keeping separate viewport/selection state. Native input uses `WorkspaceEditor::enqueue`; peer refresh uses stable document identity rather than viewport snapshots. Closing one clone preserves the document and last-reference close delegates to the existing save/discard policy.
- Both panes render document labels and pin/dirty/color indicators. Tab controls support drag and keyboard reorder, cross-pane drag, bounded overflow scrolling, vertical tabs, name/path sort commands and a keyboard/mouse MRU switcher. Pinned boundaries are validated before a move mutates placement.
- Horizontal and vertical synchronization use logical line/fraction and text x with origin tokens; native application preserves the target axis when that axis is not synchronized. Paged source positions use the exact asynchronous global-line facade. Pending lookups retain only the latest originating view request; one update is emitted after refinement, and the target schedules its own global viewport. Compare alignment supplies global spacer maps to paged peers and local maps to resident peers, never document text. Unchanged row maps are not reapplied each frame, preserving caret auto-scroll.
- Session layout persists pane membership, orientation, ratio, active view, pin/color/sort/vertical-tab preferences, selection, scroll and folds through PR-004 JSON. Resident view restoration is immediate. Paged global anchors are restored after the initial viewport read; scroll is reapplied after that read completes. Deferred/unavailable document tabs survive capture ID collisions.
- Process-local recently closed views retain pin, color, position and view state in a bounded 20-document projection keyed by the retained document identity; reopening is still owned by Workspace. No alternate recent-file store is introduced.
- Secondary views consume runtime font-family and theme changes. Successful macro receipts drain in their acknowledged order from the secondary surface.
- Accessibility publishes the actual visible tabs, close controls, overflow controls and MRU rows, with pane/pin/dirty/selection state and stable IDs. Focus on close/overflow does not invoke them; actions use the same selection and close adapters. MRU focus and visible row count follow the actual popover height.

## Boundaries

Paged rendering remains bounded to the core viewport contract. Selections spanning more than its supported window return the core error rather than restoring an incorrect prefix selection. Global logical-line synchronization and paged spacer projection now consume the paged navigation contract; viewport-local lines are never emitted as global positions while refinement is Pending. The worker checks immutable source identity/content state before applying results. Historical preview roots receive distinct identity from the live editor. Resident fold discovery and row mapping remain owned by PR-006/007; shared paged actor/recovery correctness remains owned by the paged editor service. Full-source compare computation remains PR-017.

No new document I/O, worker, dependency or second session file was added by the view adapter. Rendering and hit testing use the same editor rectangle, including panel and toolbar offsets. Visible tab and MRU painting/accessibility are bounded rather than traversing all tabs for draw operations.
