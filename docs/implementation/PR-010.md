# PR-010 — Split views and tab projection

State: IN_PROGRESS (2026-09-06). Read the own brief, FC-06 and editor/split interaction rules. Inspected current `bareline-workspace-split.png` and `bareline-compare-dark.png` before defining logical pane geometry. The written rule requiring independently labelled documents in both panes applies.

Scope: a neutral app view controller projects PR-004 `SessionTab`/`ViewState` IDs and split layout. Clone operations share the same document ID; document bytes, mutation mailbox, save/dirty state and recovery stay with the document owner. Two-pane geometry, independent view state, pinned-safe reorder, move/clone/close, origin-token scroll synchronization and compare spacers belong here. The session owner supplies the additive serialized layout; integration owns actual EditorSurface sharing and native command/input/draw wiring. No separate document storage or persistent file is introduced.

`crates/app/src/views.rs` now provides `ViewController::from_session/new`, `add_document`, `clone_to_other`, `move_to_other`, `close`, `set_view_state`, independent persisted folds, active/MRU view projection, pinned-safe drag/keyboard reorder, `geometry`, `write_session` and origin-token `begin_scroll/receive_scroll`. Clone allocates only a new SessionTab ID with the same document ID. Closing one clone bypasses document dirty-close protection until the last reference; the document owner still checks pending edits/I/O and dirty state. `geometry` limits layout to one or two panes and finite bounded ratios.

`AlignmentMap` builds arithmetic view spacers from monotone paired line ranges, checks matching unchanged gaps and overflow, and supports line-to-view/view-to-line mappings. `document_line` returns `None` for spacer rows. Scroll synchronization carries logical line/fraction and text x, maps spacers to the next real target line, and rejects replayed origin tokens to prevent echo. It does not use raw scrollbar pixel equality.

The session lane added `SessionLayout` and per-view `folds` to PR-004's existing versioned JSON schema; this controller consumes that schema without another file. The decoder's corrupt-layout fallback remains owned/tested there. The controller stores no document content/service and does no I/O.
