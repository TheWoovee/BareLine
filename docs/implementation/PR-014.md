## Implemented scope

- Recording consumes successful editor input, power-command and search-navigation receipts from the workspace and secondary view. Producers stamp a shared completion sequence; the actual native consumer passes the combined receipts through the controller's ordered normalization. Command arguments are preserved, clipboard text is captured, and generic caret receipts do not duplicate acknowledged search navigation.
- Playback supports once, N times and until EOF, cancellation, bounded/no-progress safeguards, failure location and resume. It waits for accepted asynchronous edits and search selections, pins the source document, and rejects superseded search query/document revisions before advancing. Optional delayed typing uses normal editor edits. Whole-run undo grouping is not implemented; normal per-edit undo remains available.
- The macro manager provides selection, rename, repeat count, typing delay, shortcut assignment, save, import and export. Thirty-two stable saved-command slots survive rename/restart. Shortcut assignment uses the existing keymap conflict validation and persistence path.
- Persistence uses versioned TOML, bounded file/library sizes, background I/O and atomic replacement. Initial loading stages the entire library before publication; recording, mutation and saving remain disabled until successful loading. Read/parse failure leaves storage unready with retry. Rename validates serialized and aggregate budgets before mutation.
- External definitions use explicit executable/argv configuration or explicitly granted shell execution. File, directory, selection, line, column and trusted workspace placeholders are consumed by the native run path; unavailable context is refused. Paged line/column preparation runs in a cancellable bounded worker. Imported configuration does not carry execution grants.
- The process supervisor captures stdout/stderr, reports exit/failure/cancellation, bounds output payload and chunk overhead, and terminates the Windows process tree using a kill-on-close Job Object. The launcher creates the child suspended without a console window, assigns the Job Object, then resumes it. This provides lifecycle cleanup, not a security sandbox.
- Output uses a virtual list with keyboard selection/activation, scrolling, copy, clear, save and close. File/line/column links resolve relative to the originating process directory and navigate after loading, including paged documents. Output is not interpreted as terminal control or HTML.
- Native event/draw ordering, command enablement/reasons, focus, active theme, manager text/IME handling and accessibility actions are connected to the host. The trusted workspace settings getter is consumed by both resident and paged command preparation.
