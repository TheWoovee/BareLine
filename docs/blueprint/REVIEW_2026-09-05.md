The foundation contracts still need correction before the package should be called implementation-ready. Current mockups are useful visual concepts, but are incomplete interaction specifications.

No application source, Cargo manifest, runnable binary, executable tests or performance results exist in this workspace. All 27 tracker rows are NOT_STARTED. The implementation scores below therefore assess the **plans**, not working software.

**What is good and should be kept**

- The editor-first default, familiar menus, hidden optional panels and searchable commands give the product a clear identity.
- The requirements take recovery, encoding preservation, external changes and safe writes seriously.
- A shared document model, immutable revisions and normal transactions for editing, macros, extensions and merges are sound architectural goals.
- Streaming results, sparse indexes, long-line virtualization and bounded background work address the intended large-file audience.
- Extension process isolation, portable operation and platform-neutral core boundaries are sensible.
- Measurement starts in PR-001. Keeping performance results informational while requiring correctness is consistent with the owner's stated policy.
- The PR briefs include failure scenarios, not just happy-path acceptance.
- Current screens are markedly more coherent than the root marketing boards.

**Highest-priority changes**

The findings below concern specifications and planned behavior. No running-code bug or exploit was reproduced because there is no application implementation here. P1 means resolve before implementing the affected foundation or shipping its behavior; P2 means resolve during the relevant feature milestone.

1. **P1 — Choose a coherent text and raw-byte model.** [ADR-02](D:/Notepad_REq/Bareline_Product_Blueprint/07_DECISION_LOG.md:73) and [PR-007](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-007_ENCODING_EOL_AND_UNICODE_FIDELITY.md) call the internal sequence UTF-8 while retaining invalid UTF-8 unchanged and placing undecodable bytes in an unspecified reserved code-point range. Arbitrary bytes cannot simultaneously satisfy a valid Rust UTF-8 string contract; a valid private-use range also needs collision handling. Specify raw byte storage, decoded display spans, boundary APIs and an unambiguous escape/provenance representation. Define conversion of escaped bytes to a *different* encoding. Acceptance needs malformed UTF-8, unpaired UTF-16, real private-use characters, partial edits and byte-identical untouched saves.

2. **P1 — The selected codec library does not cover the promised format matrix.** [PR-007](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-007_ENCODING_EOL_AND_UNICODE_FIDELITY.md) assigns UTF-32 and save conversion to encoding_rs. Its documentation states that UTF-32 is unsupported and UTF-16LE/BE have no encoder support. Provide explicit UTF-16 encoders, UTF-32 codecs and a named supported code-page matrix. Decode/re-encode alone also does not establish exact original-byte preservation for all legacy mappings; retain original source spans where necessary. [encoding_rs documentation](https://docs.rs/encoding_rs/latest/encoding_rs/)

3. **P1 — Paged snapshots, undo and recovery need durable original bytes.** [PR-002](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-002_PAGED_DOCUMENT_ENGINE_AND_CORE_UNDO.md:122) requires undo independent of the original file, but its base pages are evictable. [PR-004](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-004_FILE_LIFECYCLE_TABS_SESSIONS_AND_CRASH_RECOVERY.md) journals edit operations and base identity/hash without defining how the original base survives a crash followed by external modification. A hash detects a mismatch; it cannot recover missing bytes. Define what is copied/pinned/spooled before edits become durable, what a snapshot guarantees when the backing file changes, and how checkpoint/manifest ordering works. Test edit → eviction → external truncate/replace → undo; also crash → disk changes → recovery. [PR-004](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-004_FILE_LIFECYCLE_TABS_SESSIONS_AND_CRASH_RECOVERY.md:106) must not present an incomplete collection of loaded pages as an ordinary whole-document Save As: use a clearly named partial-export action with unavailable ranges.

4. **P1 — Specify the backing store for huge transcoded files.** [Implementation storage plan](D:/Notepad_REq/Bareline_Product_Blueprint/02_IMPLEMENTATION.md:164) sends all non-UTF-8 text into edit-store segments; the edit-store description does not provide a disk-backed transcode cache or quota. Streaming into an ever-growing memory store is still whole-file materialization. Define paged temporary UTF-8 storage, raw-to-logical offsets, available-length progress, disk-full/cancel behavior, ACLs and cleanup. Validate a multi-GB UTF-16 file with measured peak memory and temporary disk usage.

5. **P1 — Correct newline and indexing invariants.** [PR-002](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-002_PAGED_DOCUMENT_ENGINE_AND_CORE_UNDO.md:57) says counting 0x0A gives a correct newline count, while FR-009 supports CR-only and mixed EOL. For example, a CR-only file containing a, CR, b, CR has line boundaries but no LF bytes. Define CR/LF/CRLF handling across piece boundaries, exact versus unknown newline aggregates for unread pieces, and indexing updates while edits and background reads overlap. Add split-CRLF, CR-only, no-final-newline and unindexed-middle-edit fixtures.

6. **P1 — Regex streaming is underspecified and can lose or invent matches.** [PR-005](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-005_SEARCH_REPLACE_AND_RESULTS_ENGINE.md) requires line-ended chunks no larger than 16 MiB; [PR-003](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-003_VIRTUALIZED_EDITOR_SURFACE_INPUT_AND_SELECTION_MODEL.md) explicitly requires a 20 MB single-line fixture. Both rules cannot hold for that input. Textual pattern classification also misses newline-capable forms such as a hexadecimal newline escape and does not establish lookbehind, beginning/end-of-subject or empty-match behavior. PCRE2 partial matching requires retaining subject context and rerunning; it is not a transparent resumable matcher. Define supported semantics, overlap/context limits, chunk flags, zero-length advancement and cancellation inside expensive matches. Show truncation/incompleteness in the UI and prevent an incomplete search from appearing to be an exhaustive replacement preview. [PCRE2 multi-segment matching](https://www.pcre.org/current/doc/html/pcre2partial.html)

7. **P1 — Bind workspace replacement to the approved preview.** [PR-026](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-026_REPLACE_IN_FILES_AND_WORKSPACE_REPLACE.md) previews in phase 1 and reopens/rematches closed files in phase 2 without an explicit preview-to-apply identity/revision check. A file can change between those phases; the normal save conflict check cannot alone prove it is still the version the user reviewed. Persist preview fingerprints and selected-match identities; revalidate and skip/re-preview changed files. Handle a closed file becoming an open dirty document. Specify collision-safe backup names and a durable per-file completion record so a crash does not erase the promised exact result summary.

8. **P1 — Resolve source growth and source-change races.** [PR-015](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-015_FILE_WATCHING_MONITORING_TAIL_AND_SAFE_REMOTE_PATHS.md) uses a Paged source for tail, while ADR-03 invalidates that source whenever size or write time changes. Define append-only generations separately from overwrite/truncation, including verification of the old partial last page. A Resident source is immutable only after its streaming copy completes, so specify changes during initial loading too. Saving must distinguish the revision being written from edits arriving during the save and state what external-write races can and cannot be prevented.

9. **P2 — Replace contradictory threading and memory rules with enforceable budgets.** [The per-document thread design](D:/Notepad_REq/Bareline_Product_Blueprint/02_IMPLEMENTATION.md:170) conflicts with [the no-background-thread-at-idle rule](D:/Notepad_REq/Bareline_Product_Blueprint/02_IMPLEMENTATION.md:278) and with watchers/worker pools. Five thousand tabs cannot sensibly imply five thousand dedicated document threads. Keep actors as logical mailboxes scheduled on bounded workers. Specify aggregate cache limits across documents, snapshot retention, clipboard byte caps, result/decoration caps, queue backpressure and spill limits. Zero ongoing CPU work is a better idle contract than zero sleeping worker threads.

10. **P2 — Repair dependency order before assigning implementation waves.** [PR-005](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-005_SEARCH_REPLACE_AND_RESULTS_ENGINE.md:56) needs PR-007's transcoder from a later wave; PR-004 uses future encoding and trust services; [PR-016](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-016_EXTENSION_PLATFORM_AND_ISOLATED_PLUGIN_MANAGER.md:69) needs the later PR-018 updater; PR-013 consumes PR-006's hook without listing it. Blindly adding dependencies can introduce cycles, especially PR-004 ↔ PR-007. Extract early neutral contracts and safe stubs, split work where needed, and state which later integration tests complete each feature. The listed critical paths also include links absent from the dependency table, such as PR-013 → PR-019.

11. **P2 — Tighten edit, diff and extension contracts.** [PR-004](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-004_FILE_LIFECYCLE_TABS_SESSIONS_AND_CRASH_RECOVERY.md:72) uses revision inequality for dirty state; that cannot distinguish returning to a saved content state unless revisions/savepoints are explicitly designed for it. Use savepoints independent of monotonic job revision IDs. [PR-006](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-006_POWER_EDITING_MULTI-CURSOR_COLUMN_LINES_AND_BOOKMARKS.md:93) promises one undo across a cross-document move despite independent per-document transactions; define coordinated commit/undo or an explicit alternative. [PR-025](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-025_DIFF_CORE_ENGINE.md:75) must compare normalized content when checking normalized hashes, bound whole-input anchors and output hunks, and define cancel/error results. Its 'accept all yields byte-identical target' property needs qualification when ignore options are enabled. [PR-027](D:/Notepad_REq/Bareline_Product_Blueprint/PRs/PR-027_FIRST-PARTY_EXTENSIONS_JSON_XML_AND_HEX.md:75) must distinguish original-file bytes from transcoded snapshot bytes for Hex, and formatters need chunked/staged edits compatible with the IPC frame cap.

12. **P1 before release — Complete update trust and reproducibility semantics.** [The signing plan](D:/Notepad_REq/Bareline_Product_Blueprint/06_OPEN_SOURCE_AND_DISTRIBUTION.md:57) and PR-018/020 specify signature checks but not metadata freshness, anti-rollback persistence, authorized publisher identity or an independent recovery path after the sole trusted signing key is compromised. A revocation list signed by that same compromised key is not by itself a recovery trust anchor. Define those policies without inventing cryptography. Clarify who performs offline minisign signing and how CI waits for it. Sign inner executables before final packaging, then hash/sign final artifacts; compare normalized unsigned payloads for build reproducibility and document signing differences. [The Update Framework specification](https://theupdateframework.github.io/specification/)

13. **P2 — Correct parity and readiness claims.** [The parity matrix](D:/Notepad_REq/Bareline_Product_Blueprint/05_NOTEPADPP_PARITY_MATRIX.md) marks some not-yet-built features Equivalent/Extension; those should be planned delivery routes in a separate column. English-only does not equal multilingual feature coverage, and three extensions do not establish ecosystem compatibility. Add requirement → command/API → PR → test → evidence links and a migration coverage report. Keep performance non-gating as requested; label missing targets honestly. The fixed 8.9.8 comparison baseline and 'current stable' need an explicit update policy.

14. **P2 — Prove real input and accessibility early.** RecordingBackend tests are valuable but deterministic monospace metrics cannot prove DirectWrite shaping, BiDi caret affinity, IME candidate placement, native menu focus or screen-reader navigation. Bring a small Windows input/accessibility prototype forward alongside PR-003/023. Define offscreen TextPattern range movement, high-contrast behavior and the conflict between 'Escape returns to editor' and 'restore focus to the anchor'. Keep later PR-024 for completion and verification, not the first feasibility check.

**Other contradictions and missing decisions**

- ADR-34 says later relicensing is a one-line change; the distribution document correctly limits that convenience to sole-owner code before external contributions. Put that qualification in the authoritative ADR. Do not assume DCO sign-off transfers copyright or grants unrestricted relicensing rights. [Mozilla MPL FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)
- Telemetry is described as excluded entirely, absent in v1 unless later opted in, and 'none, ever'. Choose one policy.
- Zero enabled extensions is confused with 'never installed': after disabling all extensions, must the runtime be uninstalled automatically or retained for offline reuse? Separate process/memory cost from disk lifecycle.
- FR-021A requires ignoring encoding/BOM metadata; the proposed CompareOptions and compare UI omit it.
- The theme/control docs use surface.elevated versus surface.raised, and reference focus and mark.style1–5 without a complete authoritative default token table.
- Settings show 12 pixels while the brand specifies 12 points. At 96 DPI these are different sizes. Tab display width is also not the same setting as how many spaces pressing Tab inserts.
- A syntax comment containing 'tokio', a log mentioning a build, or an opened user file using an async library is not evidence that bareline.exe violates its dependency policy. Avoid misleading Bareline configuration examples, but do not confuse arbitrary editable content with shipped architecture.
- The regex parity promise needs a documented Boost.Regex-to-PCRE2 compatibility matrix, including replacement syntax.
- Bareline's admitted plugin/localization differences need prominent migration documentation; do not imply drop-in compatibility with Notepad++ DLL plugins.
- Supported Windows build floor, filesystem/remote-save guarantees, exact language and encoding inventories, resource defaults and maintenance ownership remain unspecified.
- XML tools need explicit external-entity/DTD/network behavior and depth/resource limits. JSON formatting needs number/string preservation fixtures and protection from excessively deep input.
- Recovery durability needs a defined flush/acknowledgment model and user-visible failure when recovery storage becomes full/unavailable. 'Five seconds' cannot be unconditional if writes are failing.
- File metadata policy should explicitly cover ACLs, timestamps, hard links, alternate streams and reparse points. Atomic replacement changes file identity; the planned choice needs documented semantics and tests.
- PR-018 introduces a Notepad++ migration helper without a complete FR or dedicated acceptance coverage; define its import matrix and opt-in behavior.
- Benchmark terminology mixes first frame, first paint and first interactive viewport. Specify start/stop events, cold-cache procedure, warm-up, sample counts, outliers, timeouts and baseline hashes. Report peak aggregate memory and open-document sessions, not only empty idle.
- Requirements label Notepad++ 1/5 GB behavior as non-comparable before local baseline measurements are supplied. Record a measured completion time or timeout instead of assuming failure.

**Recommended sequence**

1. Correct the P1 storage, encoding, indexing, regex and recovery contracts, then update the authoritative ADRs and every affected PR brief.
2. Prototype the difficult foundations: paged edit/undo/recovery under external change; UTF-16/32 and malformed-byte round trips; regex boundaries/long lines; actual Windows IME/BiDi/AccessKit interaction.
3. Repair dependencies and split subsystem epics into reviewable increments. Keep all agreed v1 scope visible; add a usable internal milestone for open/edit/save/search/recovery.
4. Create the editable design master and missing safety/interaction states. Correct theme tokens and finalize the vector identity.
5. Implement against explicit requirement/test mappings; collect performance from the first runnable build and publish only measured comparisons.

The strongest next investment is a verified foundation and coherent interaction source. Additional feature breadth or more showcase screenshots would not resolve the current implementation risks.
