# What the findings mean for users and product readiness

This table connects engineering work to the job a user is trying to finish. “Business impact” here means blocked work, data confidence, accessibility, support burden and evidence needed to make product claims. No customer, revenue or adoption measurements were supplied, so no commercial impact numbers are invented.

| User outcome | Current evidence and friction | Impact / required outcome | Work owner |
|---|---|---|---|
| Edit, save and resume ordinary work | Native resident and 3.16 MB paged edit/save/reopen checks verified bytes; a private session restored two clean tabs in order with the active document | Keep these working paths as regressions while fixing overwrite, recovery and lifecycle behavior | [Native coverage](ui-ux/coverage.md), file-safety PRs |
| Save work to an existing destination | Native Save As overwrite confirmation ends in conflict; a controlled concurrent-writer reproduction loses the displaced bytes | A core delivery workflow cannot be trusted until consent, destination identity, commit receipts and conflict recovery agree | [T03](prs/PR-T03-save-destination-consent.md), [T04](prs/PR-T04-preserve-concurrent-writes.md) |
| Start or upgrade without affecting unrelated data | Generated junction test lets startup cleanup delete outside its intended TEMP root; failed profile migration does not retry; actual `--version` mutates the private profile/cache | Startup must stay within owned data, migration must be resumable, and informational modes must not perform unrelated persistent work | [T17](prs/PR-T17-side-effect-free-launch-parsing.md), [T01](prs/PR-T01-owned-cache-cleanup.md), [T02](prs/PR-T02-resumable-data-migration.md) |
| Enter commands/options without changing document content | Native Run/Go To fields are absent from UIA; Compare options also retains Editor focus and permits a background edit action | Assistive and keyboard users need a single correct input owner and reliable dismissal before these workflows are safe | [UI/UX findings and modal plans](ui-ux/findings.md) |
| Discard a draft and know recovery will respect that choice | Source-confirmed blocking cleanup and silent deletion-failure path; native Recovery Center briefly reports empty before discovery completes | Keep the UI responsive, persist discard intent, distinguish pending cleanup from completed cleanup, and show truthful recovery states | [T05](prs/PR-T05-async-recovery-retirement.md), [U05](ui-ux/PR-U05-recovery-center-loading-refresh.md), UI focus plans |
| Navigate and keep working while background jobs finish | Reproduced cancellation/worker scheduling defects; source-confirmed failed CLI requests retain capacity and closed-tab navigation can strand a task slot | One failed or abandoned operation must not prevent later work or move focus/caret into the wrong document | [T06](prs/PR-T06-task-terminal-states.md), [T07](prs/PR-T07-shared-worker-scheduling.md), [T18](prs/PR-T18-launch-request-lifecycle.md) |
| Repeat routine work through macros and tools | Native single-character macro record/playback and a harmless explicit command with captured output pass; the empty Macro Manager has an unusable Close button and Run input ownership is defective | Preserve working automation while fixing manager state and safe input; a feature's successful core does not excuse an unusable entry/exit path | [U06](ui-ux/PR-U06-macro-manager-close-state.md), modal plans |
| Search, replace, compare and review multi-file changes | Resident Replace All/undo and compare copy/undo work. Switching from paged search to another document can retain stale counts and unavailable replacement actions. The full native folder replacement/rollback matrix is not established | Bind results to the current document and revision; retain exact blocked/unexecuted cases rather than calling the entire refactoring workflow accepted | [U09](ui-ux/PR-U09-document-bound-find-state.md), [Native coverage](ui-ux/coverage.md), [T09](prs/PR-T09-reliable-test-evidence.md), [T14](prs/PR-T14-current-capability-ledger.md) |
| Adjust preferences and undo an unwanted change | Settings autosave and confirmed Reset Section work, but Revert does nothing after autosave advances its baseline | Give Revert a useful, explicit scope and preserve that baseline across writes so users can recover from an unwanted live change | [U10](ui-ux/PR-U10-settings-revert-contract.md) |
| Understand available actions and recover from errors | Duplicate/clipped notifications, dense menus, mismatched popup theme and inconsistent accessible focus were observed | Make actions findable, current mode visible and error details readable once, with a clear next action | [U02](ui-ux/PR-U02-notification-routing.md), [U03](ui-ux/PR-U03-native-popup-theme.md), [U04](ui-ux/PR-U04-menu-information-architecture.md), other UI plans |
| Use optional first-party capabilities in a real distribution | Four actual release-host component tests pass. Normal CI skips them; clean preview builds have no complete configured owner trust/runtime delivery | Separate functional component evidence from installable feature availability; retain fail-closed trust and document preview capability limits | [T08](prs/PR-T08-fallible-extension-workers.md), [T10](prs/PR-T10-first-party-runtime-qualification.md), [T11](prs/PR-T11-release-feature-configuration.md) |
| Rely on a faster, lighter editor and a truthful status page | Synthetic large-workload checks pass, but there is no current paired release comparison here; status/parity records conflict with current implementation | Qualify the product's main comparative claim and give the next implementor one current evidence ledger | [T15](prs/PR-T15-performance-qualification.md), [T14](prs/PR-T14-current-capability-ledger.md) |

Follow the [dependency order](IMPLEMENTOR_CONTRACT.md) and [PR index](PR_INDEX.md). Prioritize file safety and input ownership, then reliable operation states and user-facing recovery, followed by visual polish and release qualification. Platform/physical-input/signing cases listed as unexecuted in the [test report](TEST_REPORT.md) remain pending; they are neither product failures nor inferred passes.
