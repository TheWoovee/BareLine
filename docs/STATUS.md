# Status: implemented and verified

This page separates what Bareline **implements** from what has been **verified**, and by which kind of evidence. It describes the Windows x64 preview on `master` after the Phase 0 to 4 fixes of the 2026-09-30 review (October 2026). A capability that is implemented and covered by automated tests is not thereby accepted: acceptance needs the native, clean-machine and physical checks in the last columns, and most of those are still pending.

The feature table in the [README](../README.md#features) gives each area a maturity label (Stable, Preview, Experimental), and [Known issues in this preview](../README.md#known-issues-in-this-preview) lists the limitations users meet. [PARITY.md](PARITY.md) compares the feature set with Notepad++, and [ROADMAP.md](../ROADMAP.md) lists what comes next.

## Kinds of evidence

| Evidence | Where | What it shows |
| --- | --- | --- |
| Unit and integration tests | `cargo test --workspace` in the [CI workflow](../.github/workflows/ci.yml), on Windows for every pull request and push, and for the portable crates on Linux and macOS | Behavior of the crates, the editor surface and the application shell without a real window. The result for a given commit is its CI run; this page does not record pass or fail. |
| Release-profile and feature tests | [Release coverage workflow](../.github/workflows/release-coverage.yml), weekly and on tags | The core crates under `--release`, fault-injection features, and an ARM64 build (not a release asset). |
| Property tests and fuzzing | Seeded property suites in the crates; [fuzz targets](../fuzz) run nightly by the [fuzz workflow](../.github/workflows/fuzz-nightly.yml) | Editing, paged windows, codecs, diff, settings, macro, UDL and function-list imports, paged recovery and session, replacement, regex search and journal replay against generated input. |
| Native journeys | [`docs/qa/READINESS.md`](qa/READINESS.md), generated by `tests/e2e/readiness.py` from `tests/e2e/journeys.json`; run by the [native journeys workflow](../.github/workflows/native-journeys.yml) | The real editor driven through Windows UI Automation, mapped to the blueprint acceptance cases (AC-xxx). A pass is evidence toward a case, not its qualification. |
| Accessibility and visual checks | `tests/a11y` (native semantic golden and Axe scan), `tests/visual` (offscreen visual cells) | The UI Automation tree and rendering of reference surfaces. |
| Performance | [`docs/perf/README.md`](perf/README.md) and the [nightly perf workflow](../.github/workflows/perf-nightly.yml) | Hosted nightly measurements and the Bareline vs Notepad++ harness. No FC-10 qualified table exists yet. |
| Clean-machine, physical and soak checks | Manual test cases, VM lab runs, `tests/soak` | Install on clean Windows 10 22H2 and Windows 11 machines, screen readers, high contrast, input method editors, DPI, long-running soak. **Pending** for every area. |

## Release engineering

| Item | Status |
| --- | --- |
| Code signing | Not signed. A SignPath Foundation application is prepared but not submitted ([CODE_SIGNING.md](../CODE_SIGNING.md)). |
| Build provenance | Tagged previews carry GitHub artifact attestations for every asset and `SHA-256SUMS`. |
| Reproducibility | The supply-chain workflow builds the unsigned payload twice on fresh runners and requires identical bytes. |
| Binary hardening | Control Flow Guard, static C runtime, DLL search restricted to System32; checked by packaging. |
| Supported Windows versions | Installer floor 10.0.19045 (Windows 10 22H2); not yet tested on clean VMs of each version. |
| Third-party notices and SBOM | Generated for every package, including the native Lexilla, PCRE2 and SLJIT code. |
